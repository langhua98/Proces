# AI 8K 视频增强 App 技术方案（v4）

> 目标：iOS App（.ipa，在 GitHub Actions 上编译）。
> 流程：**上传视频 → 拆成照片（带编号） → AI 把每张照片生成 8K → 去掉编号 → 合成 8K 视频**。
> 要求：用最先进的技术，处理和使用都要流畅。

## 1. 需求变化带来的关键结论

1. **AI 生成 8K 必须放在云端 GPU 上做。** 8K 是 7680×4320，约 3300 万像素。手机算一帧要几十秒，还会发烫降频，1800 帧根本跑不完。
2. **8K 照片不能下载到手机。** 一张 8K PNG 约 50–100MB，一分钟视频（1800 帧）就是 100GB 以上。所以拆帧、AI、合成都在云端完成，**手机只上传原视频、看进度和预览、下载最终视频**。
3. **编号不能画进送给 AI 的画面里。** AI 放大时会把编号也一起"增强"、变形，之后就无法无损删除了。做法是：
   - 系统内部用**帧 ID** 追踪每一帧（文件名 + 数据库），送给 AI 的是**干净的原帧**
   - 编号只用在给人看的地方（App 帧浏览、对比图、导出预览），以**叠加图层**的形式显示，随时开关，不需要删除
   - 如果你要**手动拿帧去别的 AI 网站**生成，就用 **"边框编号"**：编号写在画面外加的一条边上，AI 生成回来后，按放大倍数**把边整条裁掉**，100% 不影响画面（见第 4 节）
4. **逐张照片放大会闪烁。** 每一帧单独放大时，AI 每次"脑补"出的细节都不一样，连起来播放会闪烁、细节跳动。最先进的做法是用 **视频超分辨率模型**（会同时参考前后几帧，保证画面连贯），或者用"照片模型 + 时序去闪烁"两步处理。

## 2. 总体架构

```
┌──────────────────── iOS App（SwiftUI · Swift 6）────────────────────┐
│ 选视频 → 后台断点上传 → 实时进度（Live Activity/灵动岛）→ 推送完成通知 │
│ 帧浏览（带编号叠加）· 原图/8K 对比滑块 · 4K 预览播放 · 下载 8K / 存相册 │
└────────────┬───────────────────────────────────────────────────────┘
             │ HTTPS + tus 断点续传 · WebSocket 实时进度 · APNs 推送
┌────────────▼──────────── 云端 API（FastAPI）─────────────────────────┐
│ 任务编排：Temporal 工作流（失败自动重试、断点续跑、可暂停取消）        │
│ 存储：S3 / Cloudflare R2（原视频、成片）· PostgreSQL（任务、帧状态）   │
└────────────┬───────────────────────────────────────────────────────┘
             │ 把视频切成若干段（每段约 2–4 秒，段与段之间留几帧重叠）
┌────────────▼──────── GPU 处理集群（可同时开 N 张卡）─────────────────┐
│  每段：NVDEC 硬件解码 → AI 8K 生成 → NVENC 硬件编码 8K HEVC 10-bit     │
│        （全程在显存里流转，不落盘，不存 100GB 的 8K 图片）            │
└────────────┬───────────────────────────────────────────────────────┘
             ▼
     各段无损拼接 + 原音轨混流 → 8K 成片 + 4K 预览版 + HLS 流 → 通知手机
```

### 为什么这样最快
- **分段并行**：一分钟视频切成 20 段，交给 20 张 GPU 同时处理，耗时约为单卡的 1/20
- **显存内流水线**：解码 → AI → 编码在 GPU 内完成，避开最慢的"写 8K 图片到硬盘"这一步
- **硬件编解码**：NVIDIA NVDEC/NVENC 支持 8K HEVC / AV1，不占用 AI 计算
- **"拆成照片"仍然保留**：每一帧都有唯一帧号，可以单独查看、重新生成、替换；只是不用把 8K 图片全部存盘

## 3. AI 8K 生成：模型选择

做成**可插拔的"AI 引擎"接口**，可以随时切换或对比不同的模型：

| 类型 | 代表模型（示例） | 特点 | 适合 |
|---|---|---|---|
| 视频超分（时序一致） | SeedVR2、STAR、FlashVSR 等扩散 / Transformer 视频超分模型 | 画面连贯不闪烁，细节最自然，算力需求最大 | **默认推荐**，追求最好效果 |
| 照片超分 + 去闪烁 | Real-ESRGAN、HAT、SUPIR 等 + 时序去闪烁 | 单帧细节强，速度快很多 | 追求速度 / 成本 |
| 商业 API | Topaz Video AI 等 | 不用自己运维 GPU | 快速上线 |
| 手动外部 AI | 你自己选的任意 AI 网站 / 工具 | 最灵活 | 用"边框编号"模式导出导入 |

- 放大倍数：1080p → 8K 是 4 倍，4K → 8K 是 2 倍。4 倍放大建议分两步（先 2 倍再 2 倍），或者直接用原生支持 4 倍的模型
- AI 输出的尺寸统一校正为 7680×4320（或按原视频比例），竖屏为 4320×7680
- 可选增强：**AI 补帧**（30fps → 60fps，例如 RIFE）、HDR 映射、人脸修复
- 具体用哪个模型，先用同一段视频把 2–3 个候选模型都跑一遍，在 App 里用对比滑块选效果最好的

## 4. 编号设计

| 场景 | 编号怎么处理 | 怎么删除 |
|---|---|---|
| 系统自动流程（默认） | 不画进画面，只在 App 里以叠加层显示 | 不需要删除 |
| 导出帧给人工查看 | 画在右下角（半透明底 + 白字） | 这些图只用来看，不参与合成 |
| **导出帧给外部 AI 手动生成** | **边框编号**：画面下方加一条边，编号写在边的右侧 | 导入后按 `原边宽 × 放大倍数` 把这条边裁掉，画面完全不受影响 |

导入外部 AI 生成的帧时，按以下顺序识别是第几帧：文件名 → 图片元数据 → OCR 读取边框里的编号（边框是纯色底，识别率接近 100%）。识别完成后校验：缺帧、重复帧、尺寸不一致都会列出来，缺的帧可以选择"用云端 AI 补生成"。

## 5. iOS App

| 功能 | 技术 |
|---|---|
| 界面 | SwiftUI（iOS 18+），Swift 6 并发，Observation |
| 上传大视频 | 后台 `URLSession` + tus 断点续传，切换 App、锁屏、断网都能继续 |

| 帧浏览 | 缩略图网格 + 编号叠加，点开看大图（服务端按需生成切片，像地图一样缩放 8K） |
| 效果对比 | 原图 / 8K 左右拖动对比滑块，可放大看细节 |
| 预览 | HLS 流式播放 4K 预览版（大多数 iPhone 不能流畅播放 8K） |
| 下载成片 | 后台下载 8K HEVC，保存到相册或"文件"App，也可直接分享链接 |
| 登录 | Sign in with Apple |
| 手动模式 | 导出带边框编号的帧 → 外部 AI → 导入 → 云端去边框并合成 |

## 6. 云端服务

| 模块 | 技术 |
|---|---|
| API | Python FastAPI（AI 生态都是 Python） |
| 工作流 | **Temporal**（长任务编排，每段失败自动重试，进度可查询） |
| GPU 处理 | PyTorch + TensorRT / FP16 加速；FFmpeg（NVDEC/NVENC）；PyAV 在显存中传递帧 |
| GPU 资源 | 按需租用：Modal / RunPod / Hugging Face Inference Endpoints 等，用多少付多少，没任务时为 0 |
| 存储 | Cloudflare R2（没有下载流量费，适合大文件）+ CDN |
| 数据库 | PostgreSQL |
| 编码输出 | 8K HEVC 10-bit 约 80–150 Mbps；同时输出 4K 预览版 + HLS |
| 部署 | Docker 镜像，GitHub Actions 自动构建 |

## 7. 性能与成本预估（粗略，需要实测校准）

以 **1080p 30fps、1 分钟（1800 帧）→ 8K** 为例：

| 模型类型 | 单张 GPU（H100 / 4090 级） | 20 张 GPU 并行 |
|---|---|---|
| 照片超分（Real-ESRGAN 级，TensorRT 加速） | 约 30–60 分钟 | 约 2–4 分钟 |
| 视频超分（扩散模型类） | 数小时 | 约 10–30 分钟 |

- 成片大小：8K HEVC 1 分钟约 0.6–1.1GB
- 成本主要来自 GPU 时长。等实际选定模型后，用一段测试视频实测出"每分钟视频的处理时间 / 费用"，再定价或设上限

## 8. 工程与编译

```
ios/                        # iOS App（Xcode 工程，XcodeGen 生成）
  App/ Features/ Core/ Networking/
server/
  api/                      # FastAPI
  workflows/                # Temporal 工作流：拆分 → AI → 合成
  gpu_worker/
    engines/                # AI 引擎插件：seedvr2.py、realesrgan.py、topaz.py ...
    pipeline.py             # 显存内解码 → AI → 编码
  Dockerfile
.github/workflows/
  ios.yml                   # macOS 机器编译 → 产出 .ipa
  server.yml                # 构建并推送 Docker 镜像
```

- **在 GitHub 上编译 .ipa**：`ios.yml` 在 GitHub 的 macOS 机器上用 Xcode 编译，产出 .ipa 供下载
  - 没有苹果开发者账号：产出**未签名 .ipa**，用 AltStore / 爱思助手等自签安装
  - 有账号：把证书配置到 GitHub Secrets，自动签名并上传 TestFlight

## 10. 需要你确认

1. **AI 用哪个？** 你已经有想用的 AI 模型或服务了吗？还是由我推荐并实测对比？
2. **GPU 在哪里跑？** 你有自己的 GPU 服务器，还是按需租云 GPU（需要你开账号并充值）？另外，你的 Hugging Face 上有一个 `xiaoju-cloud` 的 Space（显示为 "video relay"），它是不是要用在这个项目里？
3. **原视频**一般是什么分辨率（1080p / 4K）、多长？
4. **AI 是全自动跑**（推荐），还是需要你手动拿帧去别的 AI 网站生成？
5. 有没有**苹果开发者账号**？（决定是用未签名 .ipa 自签安装，还是走 TestFlight）
