# 视频拆帧 / 合成 API 技术方案

> 说明:需求里的 "ipa" 按 **API(后端接口服务)** 理解。如果你要的是 iOS 安装包(.ipa),告诉我,方案会改成 iOS App。

## 1. 需求理解

| 步骤 | 说明 |
|---|---|
| ① 上传视频 | 用户上传一个视频文件 |
| ② 拆帧 | 把视频拆成每一帧图片,每张图 **右下角打一个小编号**(第几帧) |
| ③ 用户处理帧 | 用户下载帧图片,可自行修改,然后把帧重新上传 |
| ④ 合成 | 把上传的帧按顺序合成视频,合成时 **可以去掉右下角编号**(可选保留) |

## 2. 技术选型

| 模块 | 选型 | 原因 |
|---|---|---|
| Web 框架 | Python 3.11 + **FastAPI** | 异步、自动生成 Swagger 文档、上传大文件方便 |
| 视频处理 | **FFmpeg**(ffmpeg / ffprobe 命令行) | 拆帧、合成最稳定、最快,支持几乎所有格式 |
| 图片处理 | **Pillow** | 打编号、去编号(贴回原图区域) |
| 异步任务 | 第一版:FastAPI 后台线程池;后期:Celery/RQ + Redis | 拆帧/合成耗时,不能阻塞请求 |
| 存储 | 本地磁盘目录(后期可换 S3/OSS) | 简单 |
| 元数据 | SQLite(后期可换 PostgreSQL) | 记录项目、帧数、fps、任务状态 |
| 部署 | Docker(镜像内装 ffmpeg) | 一键部署 |

## 3. 核心设计:编号怎么打、怎么删

这是整个方案的关键。编号是"画"到图片上的,删除时如果用 OCR 识别+修图,效果差且不稳定。所以采用 **"保留原图 + 固定位置打标"** 的方式,保证删除是**无损**的:

1. 拆帧时同时保存两份:
   - `raw/000001.png` —— 原始干净帧(服务端保留,不给用户)
   - `numbered/000001.png` —— 右下角带编号的帧(给用户下载)
2. 编号绘制规则固定且可记录:
   - 位置:右下角,距边 `margin` 像素
   - 大小:根据视频高度自适应,如 `font_size = max(12, height * 0.03)`
   - 样式:半透明黑底 + 白字,保证任何画面都看得清
   - 把编号框的精确坐标 `(x, y, w, h)` 写入元数据(每个项目一份,所有帧相同尺寸所以坐标一致)
3. 合成时去编号(`remove_label=true`):
   - 用帧号找到对应的 `raw/xxxxxx.png`
   - 把原图 `(x, y, w, h)` 这一小块区域 **贴回** 到用户上传的帧上 → 编号消失,与原视频像素一致
   - 用户对画面其他区域的修改全部保留
4. 帧号识别(合成时怎么知道上传的图是第几帧):
   - 优先按文件名 `000001.png`(下载时就是这个名字)
   - 兼容:按上传顺序 / zip 内文件名自然排序

> 备选模式 `label_mode=border`:不在画面内打字,而是在画面外扩一条边框,在边框右下角写编号;合成时直接裁掉边框。优点是 100% 不碰原画面,缺点是图片尺寸变了。可作为参数提供。

## 4. 处理流程

### 4.1 拆帧
```
上传视频
  → ffprobe 读取 fps、分辨率、总帧数、时长、是否有音轨
  → ffmpeg 拆帧:ffmpeg -i input.mp4 -vsync 0 raw/%06d.png
  → (可选)ffmpeg 提取音轨:ffmpeg -i input.mp4 -vn -acodec copy audio.m4a
  → Pillow 逐帧打编号 → numbered/%06d.png(多进程并行)
  → 打包 frames.zip 供下载
  → 任务状态改为 done
```

### 4.2 合成
```
上传帧(zip 或多文件)
  → 解析帧号、校验尺寸一致、检查缺帧
  → 若 remove_label=true:逐帧把 raw 对应区域贴回
  → ffmpeg 合成:
      ffmpeg -framerate {fps} -i out_frames/%06d.png [-i audio.m4a]
             -c:v libx264 -pix_fmt yuv420p -crf 18 [-c:a aac -shortest] output.mp4
  → 任务状态改为 done,返回下载地址
```

- fps 默认使用原视频 fps,可通过参数覆盖
- 默认带回原音轨;如果用户删了/加了帧导致长度变化,用 `-shortest` 对齐,也可选 `keep_audio=false`
- 缺帧处理策略参数:`missing=error | skip | use_original`

## 5. API 设计

基础路径 `/api/v1`,所有耗时操作返回任务 ID,客户端轮询状态。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/projects` | 上传视频(multipart `file`),创建项目并开始拆帧,返回 `project_id`、`task_id` |
| GET | `/projects/{project_id}` | 项目信息:fps、分辨率、帧数、编号框坐标、状态 |
| GET | `/tasks/{task_id}` | 任务状态:`pending / running / done / failed`,进度百分比,错误信息 |
| GET | `/projects/{project_id}/frames` | 帧列表(分页),每帧的预览 URL |
| GET | `/projects/{project_id}/frames/{n}` | 下载第 n 帧(带编号) |
| GET | `/projects/{project_id}/frames.zip` | 下载全部带编号的帧 |
| POST | `/projects/{project_id}/compose` | 上传帧(zip 或多文件)+ 参数,开始合成,返回 `task_id` |
| GET | `/projects/{project_id}/output` | 下载合成后的视频 |
| DELETE | `/projects/{project_id}` | 删除项目及所有文件 |

`POST /compose` 参数:

| 参数 | 默认 | 说明 |
|---|---|---|
| `remove_label` | `true` | 是否去掉右下角编号 |
| `fps` | 原视频 fps | 输出帧率 |
| `keep_audio` | `true` | 是否带原音轨 |
| `missing` | `error` | 缺帧时的处理方式 |
| `codec` | `h264` | 输出编码(h264 / h265) |

示例:
```bash
# 1. 上传并拆帧
curl -F "file=@demo.mp4" http://localhost:8000/api/v1/projects
# → {"project_id":"p_abc","task_id":"t_1"}

# 2. 查询进度
curl http://localhost:8000/api/v1/tasks/t_1

# 3. 下载带编号的帧
curl -o frames.zip http://localhost:8000/api/v1/projects/p_abc/frames.zip

# 4. 修改后上传合成(去编号)
curl -F "file=@frames_edited.zip" -F "remove_label=true" \
     http://localhost:8000/api/v1/projects/p_abc/compose

# 5. 下载视频
curl -o out.mp4 http://localhost:8000/api/v1/projects/p_abc/output
```

## 6. 目录结构

代码:
```
app/
  main.py            # FastAPI 入口
  api/routes.py      # 接口
  services/
    probe.py         # ffprobe 读取视频信息
    extract.py       # 拆帧 + 提取音轨
    label.py         # 打编号 / 去编号
    compose.py       # 合成视频
  tasks.py           # 后台任务与进度
  models.py          # SQLite 数据模型
  config.py          # 配置(存储目录、大小限制等)
tests/
Dockerfile
requirements.txt
```

数据存储:
```
data/{project_id}/
  input.mp4
  audio.m4a
  meta.json          # fps、分辨率、帧数、编号框坐标
  raw/000001.png ...       # 原始干净帧
  numbered/000001.png ...  # 带编号帧
  frames.zip
  upload/            # 用户上传的帧
  out_frames/        # 去编号后的帧
  output.mp4
```

## 7. 性能与限制

- **磁盘占用大**:1080p 一帧 PNG 约 2–4MB,1 分钟 30fps = 1800 帧 ≈ 3–7GB(原图+编号图两份)。对策:
  - 编号帧可选输出 JPG(`format=jpg`,体积小 5–10 倍),原始帧保持 PNG 保证无损
  - 限制上传大小/时长(配置项,如默认 500MB、5 分钟)
  - 项目过期自动清理(如 24 小时)
- **速度**:打编号用多进程并行;ffmpeg 使用多线程
- **大文件上传**:流式写盘,不一次性读入内存
- **可变帧率视频(VFR)**:拆帧前统一转成恒定帧率,避免合成后音画不同步

## 8. 安全

- 校验上传文件类型(ffprobe 能识别才接受)
- 解压 zip 时防路径穿越(`../`)和 zip 炸弹(限制文件数和总大小)
- 调用 ffmpeg 用参数列表,不拼接 shell 字符串
- 可选 API Key 鉴权
